# PowerPulse

A voice and AI business copilot for small online sellers, built as a **self-hosted MCP server** (Streamable HTTP) for the **Alexa+ track** of *Build, Ship, Shape: Amazon Developer Hackathon*.

Ask your store "Why did my sales drop this week?" and get an answer computed from your own data: which category fell, what is running low, where payments failed. **Every number is computed in code, never guessed by AI.**

- **Live demo:** https://powerpulse-x2z2.onrender.com (free host, may take about a minute to wake up)
- **MCP endpoint:** https://powerpulse-x2z2.onrender.com/mcp
- **License:** MIT

## Tools (all read-only)
| Tool | What it answers |
|---|---|
| `list_orders` | Latest orders with ids, customer first name, status and total |
| `get_recent_orders` | Orders and revenue in the last N hours, and which need action |
| `get_low_stock_products` | Products at or below reorder level, ranked by days of cover |
| `analyze_sales_drop` | Last N days vs the N before, by category, with likely drivers (low stock, failed payments) |
| `find_abandoned_carts` | Idle carts by value, with a drafted recovery message |
| `draft_customer_reply` | Drafts a reply from the real order status and store policy. Drafts only, nothing is sent |

## About the data (please read)
The product catalogue (283 power tools) is real and comes from my own store project, Rohit Power Tools. My store had only one real order, so the **orders, failed payments and abandoned carts in the demo are synthetic**, generated by `npm run seed:demo` into a separate database. Every demo document has `isDemo: true`. The demo is built so that in the last 7 days one category sells less because its best sellers run low and their payments fail, which lets the analytics show a real, explainable answer.

## Run it locally
Requires Node.js 20 or newer.

```bash
git clone https://github.com/Mudgal09/powerpulse.git
cd powerpulse
npm install
npm start          # web UI: http://localhost:3000   MCP: http://localhost:3000/mcp
npm test           # evaluation cases (no database needed)
```
With no configuration it runs on built-in sample data (`DATA_SOURCE=sample`).

### Use your own MongoDB
Copy `.env.example` to `.env` and set:
```
DATA_SOURCE=mongo
MONGODB_URI=<your connection string>
MONGODB_DB=<database name>
ALLOWED_ORIGINS=http://localhost:3000
```
Helpers: `npm run inspect:mongo` (prints field names of your collections, personal fields redacted) and `npm run seed:demo` (previews, add `-- --confirm` to write a separate `<db>-demo` database from your real products). A read-only database user is recommended for deployment.

## Try the MCP endpoint
```bash
curl -s -X POST https://powerpulse-x2z2.onrender.com/mcp \
  -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```
It speaks MCP protocol version 2025-11-25 over Streamable HTTP in stateless mode. `GET /mcp` returns "Method not allowed" by design; open the live demo page to try the same tools in a browser (it is a simulated Alexa+-style experience with voice input and read-aloud). I have not tested it with a live Alexa+ device or account.

## Design notes
- `src/analytics.js` holds pure functions that produce all facts. The language model never invents numbers.
- Tools are read-only, replies are drafts, and only first names are exposed. The MongoDB adapter excludes address and payment-secret fields.
- `/mcp` and `/api` reject unknown browser origins (`ALLOWED_ORIGINS`, plus Render's own URL).
- Optional Gemini wording polish for drafted replies (`GEMINI_API_KEY`); facts always come from the database, and the app falls back to the plain draft.
- `eval/` has ground-truth cases, an end-to-end MCP client test (`eval/mcp-smoke.js`) and a latency benchmark (`npm run latency`).

## Project structure
```
src/server.js        Express + MCP Streamable HTTP, web UI API
src/tools.js         MCP tools
src/analytics.js     Pure functions computing all facts
src/data/            Data sources: sample, MongoDB adapter and field mapper
src/seed/            Synthetic demo-data generator
scripts/             inspect-mongo, seed-demo, import-olist
public/index.html    Web UI
eval/                Tests and benchmarks
```
